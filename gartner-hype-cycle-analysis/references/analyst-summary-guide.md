# 分析师小结与年度对比判断

## 小结的职责

章节正文负责列证据，小结负责解释证据组合。小结不是表格复述，也不是免责声明。推荐结构：

推荐在飞书中使用以下可审计句式，并按篇幅合并成一段：

```xml
<p><b>小结（分析师判断）</b>：变化事实……（G1 p.xx；G2 p.yy）。意义/Gartner 判断：……。企业含义：……。证据边界：……。</p>
```

“证据边界”仅在需要时保留；“变化事实”“意义/Gartner 判断”“企业含义”不可省略。分析师推理要与 Gartner 原话分开，必要时使用 `` `<推理>` `` 标记。

## 五类小结

### 量化指标后

把曲线阶段、收益、渗透率、成熟度和采用时间放在一起解释。优先识别组合信号：

- 阶段不变 + 渗透率上升 + 采用时间提前：规模化采用加速，通常不是范式突变。
- 进入低谷 + 渗透率上升 + 成熟度升档：能力普及但预期回落，竞争转向可验证结果。
- 收益：高（High）+ 市场渗透率较低：价值方向清楚，规模化路径仍未验证。
- 多项持平：市场判断稳定；分析重点应转向定义、架构边界、生态或实施条件，不要虚构变化。

### 定义与叙事后

说明概念边界、评价单位或价值重心的变化。例如从组件集合转为平台、从交互入口转为任务闭环、从产品市场转为交付模式。指出这会改变哪些产品比较或采购标准。

### 驱动因素后

区分需求侧、供给侧、成本、组织和生态驱动。判断变化是短期事件、厂商推动，还是持续的结构性需求，并说明它会推动采用还是只提高关注度。

### 障碍后

判断瓶颈从哪里移到哪里：功能、集成、人才、治理、成本、标准、供应链或可信度。把风险与阶段变化联系起来，并给出需要先建立的控制条件。

### 用户建议后

提炼 Gartner 推荐的采用姿态：观望、PoC、受控采用、规模化整合或刷新迁移。把建议转成采购和实施的评价标准，而不是重复动作清单。

明确区分 **Gartner 用户建议**（报告原文或忠实整理，附页码）与 **分析师实施建议**（基于证据的推导，标注为分析师判断或 `<推理>`）；不能把后者写成 Gartner 的直接要求。

## 年度总结

年度总结应形成 3–5 条递进判断，常用顺序：

1. 阶段与采用信号。
2. 概念或市场边界变化。
3. 价值重心和主要风险。
4. 对企业的采用、架构或采购含义。

每条都应有分析结论和证据标识。不要设置只写“证据边界”的总结项；边界可在结论之后另段说明。若条目不可比，年度总结只描述榜单/命名或证据状态，不给出采用趋势判断。

## 条目映射

- **同名且定义连续**：可直接逐字段比较。
- **改名但定义、能力和场景高度连续**：可以建立对应关系，同时标注“议题重构”或“重命名”。
- **拆分或合并**：分别列出继承和新增的范围，避免用单一箭头表现全部变化。
- **被移除或概览不再点名**：只能说明榜单或概览状态变化；若 Profile 仍存在，应继续比较 Profile，不得写成技术消失。
- **无法确认映射**：保留为两个条目，标记证据缺口。

映射表至少包含：旧名称、新名称、连续性证据、继承范围、新增范围、可比性结论。只有在可比性结论为“连续”时，才可计算年度指标变化；“部分连续”必须把继承范围和新增范围拆开解释，“不可比”不得写采用趋势。

驱动因素、障碍和建议做集合比较前，先进行语义归一化（同义词、编辑改写、拆分/合并）；仅措辞变化应标记为“编辑性变化”，不能误报为新增或删除。

若任一 PDF 或页码无法访问，保留 `` `<证据缺口>` ``，不填补页码，不引用前序 Agent 的二手表述。

## 禁止性写法

- “上表仅并列呈现两年内容。”
- “共同、新增和删除必须以原文为准。”
- “本节不把条目数量变化等同于市场规模。”
- “请关注后续章节。”

这些内容可以作为方法说明或证据边界，但不能承担小结功能。

## 最小句式检查

交付前逐段检查：

1. **变化/持平**：明确指出至少一个字段或叙事的变化，或说明“基本持平”。
2. **意义**：解释该组合为何影响市场判断。
3. **Gartner 判断**：说明阶段、边界或价值重心的移动。
4. **实施含义**：落到采用、采购、架构或治理动作。
5. **证据**：保留页码、表内字段或证据 ID；推理不得伪装成 Gartner 原话。

## 质量自检

读完小结后，读者应能直接回答：变化是什么、为什么重要、Gartner 的判断发生了什么移动、企业应如何理解或行动。每段至少有一个页码、表内字段或证据 ID。若只能知道“还需谨慎”或“证据有限”，小结需要重写。还要检查小结是否紧邻对应表格/对比段落，以及年度总结是否只引用已出现的证据。
